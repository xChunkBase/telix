# Telix

A modern, PSR-first Telegram Bot API library for PHP. One expressive API over both
webhooks and long polling, with conversations, forms, i18n, storage, plugins, and the
full typed Bot API surface.

# Full Specs

- PHP +8.3 Required
- Full coverage of **Bot API 10.2** (released July 14, 2026)
- All **388** Bot API objects as `final readonly` DTOs
- All **185** Bot API methods, fully typed — plus a `raw()` fallback for anything new
- Handling **Webhook** (with optional fast-ack) and **long polling**
- Built-in i18n (`{placeholder}` + ICU MessageFormat) with per-user locale resolution
- PSR-16 cache, conversation state, short-term memory, and an injection-safe PDO layer (SQLite / MySQL / PostgreSQL)
- Step-based conversation flows, forms with validation & auto-retry
- Plugins, attribute-discovered handlers, middleware
- Inline/reply keyboards, pagination, flood protection, scheduled nudges, broadcaster
- PSR-3 / 7 / 11 / 16 / 17 / 18

## Install

```bash
composer require telix/telix guzzlehttp/guzzle
```

Telix auto-detects any PSR-18 HTTP client; Guzzle is the easiest. If you already have a
PSR-18 client + PSR-17 factories, you can pass your own instead and drop Guzzle.

## Quick start

```php
<?php
require 'vendor/autoload.php';

use Telix\Telix;
use Telix\Bot\Context;

$bot = Telix::bot('123456:YOUR_TOKEN');

$bot->command('start', fn (Context $ctx) => $ctx->reply("Hello, {$ctx->from()->firstName}!"));

$bot->poll(); // long polling
```

That's a complete bot. Below is everything else.

# Core concepts

## Two ways in

**A full bot** when you want to handle updates:

```php
$bot = Telix::bot($token);           // optional: parse mode, translator, cache, logger, http…
```

**Just the API** when you only want to send something and leave:

```php
$api = Telix::api($token);
$api->sendMessage(123456789, 'Ping');
```

## Handlers & routing

Register handlers on the bot. Every handler receives a `Context`. Handlers can be a
closure, an `[$object, 'method']` callable, or an invokable class name.

```php
$bot->command('help', fn (Context $ctx) => $ctx->reply('Need a hand?'));   // /help
$bot->hears('/(hi|hello)/i', fn (Context $ctx) => $ctx->reply('👋'));       // regex on text
$bot->onText('menu', fn (Context $ctx) => $ctx->reply('Opening menu'));    // exact text
$bot->callback('cancel', fn (Context $ctx) => $ctx->edit('Cancelled.'));   // inline button press
$bot->onMessage('photo', fn (Context $ctx) => $ctx->reply('Nice shot!'));  // messages with a photo
$bot->onUpdate('edited_message', fn (Context $ctx) => $ctx->reply('Edited!'));
$bot->fallback(fn (Context $ctx) => $ctx->reply("I didn't understand that."));
```

Every registration takes an optional `priority` (higher runs first). `command()` also
takes a `description` used by `syncCommands()`.

### Command arguments

```php
$bot->command('say', fn (Context $ctx) => $ctx->reply($ctx->args() ?? 'Say what?'));
// "/say hello world"  ->  args() === "hello world"
```

## The Context

The single object your handlers work with:

```php
$ctx->reply($text, ParseMode::Html, $keyboard, quote: true);  // send in the same chat
$ctx->replyHtml($text, $keyboard);                            // shortcut
$ctx->edit($text, ...);            $ctx->editReplyMarkup($kb); // edit the current message
$ctx->answer('Done', showAlert: true);                        // answer a callback query (toast/alert)
$ctx->delete();                    $ctx->typing();            // delete, show "typing…"

$ctx->text();      $ctx->args();          // message text / everything after the command
$ctx->chatId();    $ctx->from();          // int|null / User
$ctx->message();   $ctx->callbackQuery(); $ctx->callbackData();
$ctx->param('x');  $ctx->setParam('x', 1);// per-update scratch space (shared across middleware)
$ctx->api();                              // the full BotApi for anything Context doesn't wrap
```

## Calling any Bot API method

Every method is typed and lives in its own file under `src/Method`:

```php
use Telix\Type\Enum\ParseMode;

$bot->api()->sendMessage($chatId, '*Hi*', ParseMode::MarkdownV2);
$bot->api()->sendDice($chatId);
$member = $bot->api()->getChatMember($chatId, $userId);   // -> ChatMember DTO
```

For a method Telix doesn't type yet (or a brand-new one Telegram just shipped), use the
upgrade-proof escape hatch — it takes a plain array and still resolves the return type:

```php
$bot->api()->raw('sendMessage', ['chat_id' => $chatId, 'text' => 'Hi']);
```

## Keyboards

```php
use Telix\Keyboard\InlineKeyboard;
use Telix\Keyboard\Button;

$kb = InlineKeyboard::make()
    ->row(Button::callback('Buy', 'buy:1'), Button::url('Docs', 'https://core.telegram.org'))
    ->row(Button::callback('Cancel', 'cancel'));

$ctx->reply('Choose:', replyMarkup: $kb);
```

Reply keyboards work the same via `ReplyKeyboard::make()`, plus `RemoveKeyboard`,
`ForceReply`, and a `Keyboard::from([...])` helper for quick grids.

## Conversations (steps)

Enter a step, then handle the next update for that user with `onStep`:

```php
$bot->command('name', fn (Context $ctx) => $ctx->enter('ask_name'));

$bot->onStep('ask_name', function (Context $ctx) {
    $ctx->reply("Nice to meet you, {$ctx->text()}!");
    $ctx->finish();                 // or ->advance('next_step') to chain
});
```

State is short-lived (bounded TTL) and stored via the cache.

## Forms & validation

Multi-field flows with validation, error messages, and automatic re-prompting:

```php
use Telix\Form\Form;
use Telix\Form\Expect;

$signup = Form::create('signup')
    ->field('name', 'What is your name?', Expect::text(min: 2))
    ->field('age',  'How old are you?',   Expect::int(min: 1, max: 120))
    ->then(function (Context $ctx, array $answers) {
        $ctx->reply("Welcome {$answers['name']} ({$answers['age']})");
    })
    ->register($bot);

$bot->command('signup', fn (Context $ctx) => $signup->start($ctx));
```

`Expect` ships `text`, `int`, `regex`, `oneOf`, and message-type checks (`photo`,
`document`, `voice`, `contact`, `location`), plus `check()` for custom rules.

## Short-term memory

Per-user, TTL-bounded helpers (max 24h) for the small stateful bits bots need:

```php
if ($ctx->throttle('search', seconds: 5)) { $ctx->reply('Slow down a little.'); return; }

if (! $ctx->confirm('delete_account')) { $ctx->reply('Tap again within 15s to confirm.'); return; }

$ctx->remember('cart', ['item' => 42], ttl: 600);
$cart = $ctx->recall('cart', []);
$hits = $ctx->count('clicks');                         // rolling counter
```

## Multi-language (i18n)

```php
use Telix\I18n\Translator;

$t = (new Translator(defaultLocale: 'en'))
    ->add('en', ['hi' => 'Hello, {name}!'])
    ->add('fa', ['hi' => 'سلام {name}!']);
    // or ->loadDirectory(__DIR__ . '/lang')

$bot->withTranslator($t);

$bot->command('start', fn (Context $ctx) => $ctx->reply($ctx->t('hi', ['name' => $ctx->from()->firstName])));
```

Messages that look like ICU (`{count, plural, ...}`) are formatted via `intl` when
available; everything else uses simple `{placeholder}` substitution.

## Storage: cache, state & database

`$bot->cache()`, `$bot->state()`, and `$bot->memory()` are always available. For real
data, use the injection-safe PDO layer:

```php
use Telix\Database\Db;

$db = Db::sqlite(__DIR__ . '/bot.sqlite');
// or Db::mysql('db', 'user', 'pass'), Db::pgsql(...), Db::connect($existingPdo)

$db->insert('users', ['telegram_id' => $id, 'name' => 'Ada']);
$user   = $db->find('users', ['telegram_id' => $id]);           // one row or null
$recent = $db->select('orders',
    ['status' => 'paid', 'amount >=' => 100],                   // the operator lives in the key
    orderBy: 'created DESC',
    limit:   20,
);
$db->select('users', ['id IN' => [1, 2, 3]]);                   // IN / NOT IN / LIKE / <, >, != …

$db->transaction(fn () => /* … */ null);
```

Every value is parameter-bound and every identifier is validated, so it's safe against
injection by construction.

## Plugins & discovery

Group related handlers into a plugin:

```php
use Telix\Plugin\Plugin;
use Telix\Plugin\PluginConfigurator;

final class WelcomePlugin implements Plugin
{
    public function configure(PluginConfigurator $plugin): void
    {
        $plugin->command('help', fn (Context $ctx) => $ctx->reply('How can I help?'));
    }
}

$bot->use(new WelcomePlugin());
$bot->discover(__DIR__ . '/Handlers');   // or auto-register attribute-annotated handler classes
```

## Flood protection

```php
$bot->protect(maxUpdates: 20, perSeconds: 10, muteFor: 30);
```

Users exceeding the rate are muted for a cooldown; pass `onFlood` to customize the response.

## Scheduled nudges

Follow up with a user later:

```php
$bot->onNudge('reminder', fn (Context $ctx) => $ctx->reply('Still there?'));

$ctx->nudge('reminder', in: 3600);   // fire in 1 hour
```

Nudges are dispatched by `$bot->tick()` — long polling calls it every loop; on webhooks,
call `tick()` from a cron job.

## Broadcasting

Send to many chats with rate-limiting and resumable checkpoints:

```php
use Telix\Broadcast\Broadcaster;

$caster = new Broadcaster($bot->api(), $bot->cache());
$report = $caster->text($chatIds, 'Announcement!', ParseMode::Html);
```

## Webhook vs. long polling

```php
$bot->poll();                                   // long polling (CLI)

$bot->webhook(secretToken: $secret);            // webhook: validates Telegram's secret header
```

### Fast-ack webhooks

Reply `200 OK` to Telegram in **milliseconds**, then process the update in the background
of the same request:

```php
$bot->webhook(secretToken: $secret, defer: true);
```

Under PHP-FPM this uses `fastcgi_finish_request()`; on other SAPIs it flushes the response
and keeps running. **Caveat:** once you ack, Telegram won't retry — if the background work
crashes, that update is lost. Great for chat/UX
